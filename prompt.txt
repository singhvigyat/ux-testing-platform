You are modifying an existing Multi-Agent UX Testing Platform architecture.

IMPORTANT:
Do NOT redesign the system from scratch.
Extend the CURRENT architecture while preserving the existing Screenshot Snapshot Collector (SSC) pipeline.

The current system flow is roughly:

Playwright crawler
→ Screenshot Snapshot Collector (SSC)
→ Persona agents analyze screenshots
→ Aggregated UX report

We want to upgrade this architecture to make persona reasoning more grounded, cost-efficient, and technically credible.

Follow the instructions below.

---

GOAL

Enhance the architecture while keeping SSC as the perception layer.

Key improvements required:

1. Add DOM metric extraction
2. Introduce a structured UI Observation Package
3. Improve persona behavior modeling
4. Add UI segmentation
5. Add a conflict detection stage
6. Keep the number of LLM calls minimal

---

STEP 1 — Add DOM Metric Extraction Layer

Extend the Playwright crawler so that besides screenshots it also extracts UI metrics.

Extract metrics such as:

* computed font-size
* line-height
* button height / width
* clickable element size
* number of navigation items
* color contrast
* element bounding boxes
* DOM hierarchy depth
* visible CTA elements

This should be implemented as a module:

DOMObservationExtractor

Output structured JSON.

---

STEP 2 — Create UI Observation Package

Instead of sending raw screenshots to persona agents, create a structured object:

UIObservationPackage

Example schema:

{
page_url: string,
screenshot_path: string,

layout_sections: [
{ type: "header", bbox: [...] },
{ type: "navigation", bbox: [...] },
{ type: "hero", bbox: [...] },
{ type: "content", bbox: [...] },
{ type: "cta", bbox: [...] },
{ type: "footer", bbox: [...] }
],

typography_metrics: {
body_font_size: number,
heading_font_sizes: []
},

interaction_metrics: {
button_sizes: [],
clickable_elements: number
},

navigation_metrics: {
nav_item_count: number
},

accessibility_metrics: {
contrast_ratios: []
}
}

Persona agents should receive THIS object instead of raw screenshots.

---

STEP 3 — Add UI Segmentation Layer

Before persona reasoning, split the UI into logical regions.

Implement:

UISegmenter

Segments include:

* header
* navigation
* hero
* main content
* CTA
* footer

Persona agents should analyze segments individually rather than the entire page.

---

STEP 4 — Replace Simple Persona Prompts With Behavioral Profiles

Current system likely defines personas like:

"You are a 60-year-old user."

Replace this with structured persona profiles.

Example persona schema:

{
persona_name: "elderly_user",
cognitive_traits: [
"slow visual scanning",
"prefers large text",
"avoids dense navigation",
"needs strong visual hierarchy"
],
tolerance: {
dense_layout: low,
small_text: very_low
}
}

Create profiles for:

* elderly_user
* first_time_user
* developer_power_user
* visually_impaired_user

Persona agents must base reasoning on these traits.

---

STEP 5 — Persona Evaluation Stage

Each persona agent should analyze:

* UI segments
* DOM metrics
* screenshot

and produce structured findings:

{
persona: string,
segment: string,
issue_type: string,
severity: string,
explanation: string
}

---

STEP 6 — Conflict Detection Agent

Add a new stage:

ConflictDetectorAgent

This agent analyzes persona outputs and identifies contradictions.

Example conflict:

Developer persona:
"Navigation density is efficient."

First-time user persona:
"Navigation feels overwhelming."

Conflict detector outputs:

{
conflict_type: "information_density",
personas: ["developer", "first_time_user"],
explanation: "Experts prefer dense navigation but novices find it overwhelming."
}

---

STEP 7 — Final Report Generator

Aggregate:

* persona findings
* detected conflicts
* UX recommendations

Generate structured UX report.

2. All personas must analyze the SAME observation package.
3. SSC should run only once per page.
4. Persona reasoning should be parallelizable.
5. Preserve compatibility with the existing architecture.
